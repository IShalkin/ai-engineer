## Security and Risk

- [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/initiatives/agentic-security-initiative/) - CC BY-SA 4.0, released 10 December 2025 as the 2026 edition, beside the LLM-application list which is the 2025 edition, so name the list and the edition together. The ten, with the failure each names and the incident the authors anchor it to: ASI01 Agent Goal Hijack, natural-language input altering the agent's intended goal (EchoLeak); ASI02 Tool Misuse & Exploitation, legitimate tools driven to exfiltration, unsafe operations or workflow hijack (Amazon Q); ASI03 Identity & Privilege Abuse, escalation and cross-agent impersonation through cached credentials, inherited roles or unintended delegated scopes; ASI04 Agentic Supply Chain Vulnerabilities, poisoned or impersonated tools, prompts, models or MCP connections loading malicious logic **at runtime** (GitHub MCP exploit); ASI05 Unexpected Code Execution, unsafe code generation, deserialization or shell execution from crafted prompts (AutoGPT RCE); ASI06 Memory & Context Injection, poisoning RAG stores, memory or context to plant false knowledge across sessions or agents (Gemini memory attack); ASI07 Insecure Inter-Agent Communication, missing encryption, authentication or semantic validation between agents enabling tampering, replay or goal manipulation; ASI08 Cascading Failures, one fault propagating across interlinked agents and amplifying through chained autonomous actions; ASI09 Human-Agent Trust Exploitation, deception, emotional manipulation or fake explainability driving unsafe human approvals; ASI10 Rogue Agents, compromised or misaligned agents that deviate, **collude, self-replicate** or hijack workflows as insiders (Replit meltdown). ASI06 appears as "Memory & Context Injection" on the cheat sheet and as "Memory & Context Poisoning" in the project's own prose and challenge data - both are OWASP usage, so quote whichever the cited artifact uses rather than normalizing. Verified 2026-08-22 from the published cheat sheet and launch announcement; the resource page itself returned HTTP 403 to automated fetches from two clients on 2026-08-21.
- OWASP Top 10 for LLM Applications, edition 2026 (document held locally; [project site](https://genai.owasp.org/)) - CC BY-SA 4.0. The copy checked states "[Publication date to be set]", so treat it as pre-publication and re-check status before citing it as current. **The identifiers moved between editions and no longer name the same risk.** Against the 2025 list: excessive agency LLM06 becomes LLM03; supply chain LLM03 becomes LLM04; data and model poisoning LLM04 becomes LLM05; unbounded consumption LLM10 becomes LLM06; misinformation LLM09 becomes LLM07; vector and embedding weaknesses LLM08 becomes LLM09; improper output handling LLM05 becomes LLM10. Only prompt injection (LLM01) and sensitive information disclosure (LLM02) keep their number; LLM08:2026 was not recovered from the copy checked, and the fate of 2025's system prompt leakage is therefore unconfirmed here. A control mapped to a bare "LLM06" is ambiguous and changes meaning silently when the next reader resolves it against the other edition, so carry the edition with every identifier — the same rule the agentic list needs for its own editions. Its Appendix A consolidates mappings to nine external frameworks in one place, replacing the per-entry framework sections of the previous edition. Verified 2026-08-22 from the document.
- [OWASP GenAI exploit round-up](https://genai.owasp.org/) - a quarterly incident report from the project co-lead mapping each disclosed incident to both Top 10s and to a CVE where one exists; the Q1 2026 edition of 14 April 2026 covers eight: AI-assisted intrusion, an agent that ignored stop commands and deleted a live mailbox, an internal agent whose recommendation was implemented and broadened access to sensitive data, managed-platform service-agent privilege abuse, an agent-tooling source leak that became a malware lure within hours, a data-vendor dependency compromise, an actively exploited orchestration-platform RCE, and an indirect-injection exfiltration path through a dashboard's image rendering. Two uses here: it is the corpus of real agentic failures behind `SEC-01`'s abuse cases, and it is a source of adversarial cases for `EVA-01` that no build team would invent. Its own stated finding is that most of these carry no CVE at all - they are misconfiguration, autonomy and trust-boundary design flaws, so a CVE-driven vulnerability process sees almost none of them. Verified 2026-08-22.
- [OWASP Agentic Security Initiative](https://genai.owasp.org/initiatives/agentic-security-initiative/) - practical MCP and agent-security resources.
- [NIST AI 600-1](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence) - generative-AI lifecycle risk profile.
- [OWASP Agentic Skills Top 10](https://owasp.org/www-project-agentic-skills-top-10/) - AST01-AST10, v1.0 2026 edition, CC-BY-SA-4.0, OWASP incubator status at access time. Covers the skill layer rather than the protocol layer: malicious skills, supply-chain compromise, over-privileged skills, insecure metadata, untrusted external instructions, weak isolation, update drift, poor scanning, absent governance, cross-platform reuse. The distinction it draws is that MCP defines how a model reaches a tool while a skill defines what is done with it, so a package of agent instructions is itself an artifact class with its own threat model - this one included. Applies to skills this project authors or installs, not only to systems it assesses. Incubator status means the categories may still move; cite the edition. Verified 2026-08-21.
- [OWASP FinBot CTF](https://github.com/GenAI-Security-Project/finbot-ctf) - OWASP GenAI Security Project, Apache-2.0: an intentionally vulnerable multi-agent platform with real MCP tool access, whose challenges are YAML-defined and mapped to the OWASP LLM and Agentic Top 10s, CWE and MITRE ATLAS. Challenge classes are recon, policy bypass, data exfiltration, destructive action and remote code execution, detected by an event pipeline rather than by static flags. Its value here is as a source of adversarial and policy cases for `EVA-01` and as an environment for the injection tests `SEC-01` requires; running it needs an LLM key and stands up live vulnerable agents, so treat it as a lab, not a dependency. Verified 2026-08-22.
- [NIST AI 100-2 E2025](https://csrc.nist.gov/pubs/ai/100/2/e2025/final) - adversarial machine learning taxonomy and terminology, final March 2025. Organized by ML method, lifecycle stage of attack, and attacker goal, objective, capability and knowledge; covers predictive-AI attacks such as poisoning and evasion alongside generative-AI attacks including direct and indirect prompt injection. The page carries a post-final note dated 2025-06-03 recording an error on page x, so check it before quoting that page. Read it as the adversarial-attack companion to AI 600-1's lifecycle risk profile rather than a replacement `ENGINEERING_SYNTHESIS`. Verified 2026-08-21.
- [Microsoft taxonomy of failure modes in agentic AI systems v2.0](https://cdn-dynmedia-1.microsoft.com/is/content/microsoftcorp/microsoft/bade/documents/products-and-services/en-us/security/Taxonomy-of-Failure-Modes-in-Agentic-AI-Systems-v2-0.pdf) - the whitepaper carries the category text and is the citable artifact; the [announcement of 4 June 2026](https://www.microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us/) summarizes it and states the evidence base, twelve months of red-team engagements against deployed systems. v2.0 adds agentic supply-chain compromise, goal hijacking, inter-agent trust escalation, computer-use-agent visual attack, session context contamination, MCP/plugin abuse, and capability/architecture disclosure. The novel-versus-existing and safety-versus-security axes are v1.0 structure; the v2.0 announcement does not restate them and the axis wording was not extractable from the PDF, so read the axes off the whitepaper before attributing them to v2.0. Verified 2026-08-21.
- [MAESTRO](https://cloudsecurityalliance.org/blog/2025/02/06/agentic-ai-threat-modeling-framework-maestro) - Cloud Security Alliance layered threat-modeling frame, 6 February 2025: foundation models, data operations, agent frameworks, deployment and infrastructure, evaluation and observability, agent ecosystem, plus security and compliance as a vertical spanning the rest. Useful for locating an abuse case in a layer and for naming cross-layer attack paths; it is a decomposition, not a control set. A [CSA follow-up of 11 February 2026](https://cloudsecurityalliance.org/blog/2026/02/11/applying-maestro-to-real-world-agentic-ai-threat-models-from-framework-to-ci-cd-pipeline) argues the threat model should regenerate per commit and diff, so only threats a change introduces are surfaced. It is co-authored by MAESTRO's own creator and by the author of the tool it demonstrates, so it is the framework promoting itself, not independent corroboration; take the per-commit-and-diff idea and discount the endorsement. Both links are CSA blog posts rather than a specification. Verified 2026-08-21.
- [Agent Control Standard](https://agentcontrolstandard.org/) - vendor-neutral agent control plane in three tiers: platform hooks, an enforcement SDK applying declarative policy, an enterprise layer for custom classifiers. It fires a hook when an agent receives input, sends output, calls a tool, **selects which tools to use**, transitions from planning to execution, stores a memory, **executes code**, or invokes a sub-agent. Those eight are a useful completeness check for `SEC-02` gate placement; tool selection and code execution are the two most often left ungated, and an enumeration that drops them reads as complete while the highest-consequence path is open. No version number or release date appears on the site; press coverage naming one is secondary and not carried here. Verified 2026-08-21.

- [AIUC-1 crosswalk to the OWASP Agentic Top 10](https://genai.owasp.org/) - v1.0, May 2026, CC BY-SA 4.0: a bidirectional mapping between the Agentic Top 10 and AIUC-1, a separately authored six-principle standard for AI agents. Two things transfer beyond the tables. Its eight control-function codes — prevent, constrain scope, human gate, detect and trace, validate and test, policy and governance, isolate and contain, disclose and calibrate — give `SEC-01` a way to check that the controls named against an abuse case are not all the same function, which is the usual failure of a control list that looks full. And it decides primary versus secondary by threat context rather than by control type: detection is primary where the threat is invisible without it, secondary where prevention is frontline. Keep its own stated limit — the crosswalk "identifies relevance, not sufficiency", so a mapped requirement is not a mitigated risk. Verified 2026-08-22.
- [OWASP Agentic AI SecOps Framework](https://genai.owasp.org/ai-security-solutions-landscape/) - CC BY-SA 4.0, Q2 2026, splitting per-lifecycle-stage duties into agentic DevOps and agentic SecOps columns across plan, data, develop, test, release, deploy and operate, with monitor and govern cutting across. Useful as a duty checklist for `OPS-02` and `OPS-03`: signing model weights, plugin manifests and memory snapshots and validating policy bundles at deploy; registering the agent in a trust registry with a capability descriptor; monitoring memory-mutation patterns for unauthorised overwrite; and auditing reflection accuracy by comparing stated against observed planning outcomes. The same document is a sponsor-tiered vendor landscape built from self-nominations and refreshed quarterly — take the duty columns and ignore the logos, which are neither an assessment nor a recommendation. Verified 2026-08-22.

These catalogues are mostly not independent of one another. The OWASP agentic threats-and-mitigations work sits upstream of several: Microsoft's taxonomy cites it, NVIDIA's agentic safety framework builds on OWASP's threat-modelling guide, and by the project's own Q2 2026 count eighteen vendors have implemented the ASI taxonomy directly into their products — so a tool that reports findings labelled with ASI categories is not independent evidence about those categories either. Use them for **coverage**: a category present in one and absent from your abuse-case list is a gap worth checking. Do not use them for **corroboration**: two of them agreeing is one source counted twice under the independence rule in [completeness-provenance.md](completeness-provenance.md). The exception is AIUC-1, which has its own authorship, principles and requirement structure rather than descending from the same work, so agreement between it and the Top 10 is real corroboration — and is the only such pair registered here.

## Current Research Routing

- For emerging methods absent from books, search primary papers and label claims `CURRENT_PRIMARY`; distinguish experimental results from established guarantees.
- [Robust Multi-Agent LLMs under Byzantine Faults](https://arxiv.org/abs/2605.09076) and [Rethinking the Reliability of Multi-agent System](https://arxiv.org/abs/2511.10400) are current examples. Their results depend on stated graph, fault, benchmark, and agent assumptions; do not generalize them into “LLM voting is Byzantine-safe.”
- [From Governance Norms to Enforceable Controls](https://arxiv.org/abs/2604.05229) gives a six-dimension rubric (Table I, §V-D) - timing of harm, pre-action observability, rule determinacy, judgment load, reversibility, evidence clarity - for deciding whether a governance duty is enforceable at runtime or belongs in a design-time constraint, a human escalation, or assurance evidence. It routes between `SEC-02` gate placement and `REG-01` obligation ownership rather than replacing either. A single-author preprint, not a standard: cite it as a heuristic and say so. Verified 2026-08-21.
- Record paper version/date, experiment, threat/fault model, baseline, and exact imported claim. Apply ASM-01 to guarantee language.

### BFT and agent consensus route

Route Byzantine fault tolerance (BFT), quorum, voting, correlated-agent error, and consensus claims through `DST-01` plus `ASM-01`. Record membership, identities, timing, fault bound/type, independence evidence, adversary, safety/liveness property, and non-guarantees. Never import `3f+1` or another threshold without the protocol's assumptions.

### Budget-aware reasoning route

Route adaptive model depth, inference-time compute, test-time scaling, search, or deliberation through `ARC-05`, `PRM-03`, and `EVA-01`. Define a budget policy over latency, tokens/cost, calls, tool use, and risk; calibrate escalation on held-out task difficulty; measure quality-cost frontiers and exhaustion behavior. Do not equate a longer trace with better reasoning.

## Version Rule

Treat book code and framework APIs as explanatory examples. Before implementation, verify package versions, migration notes, current official API syntax, deprecated behavior, security advisories, protocol versions, and telemetry-convention stability. Pin dependencies, negotiate protocol versions explicitly, and encode compatibility tests.
